# ADR 追加手順

設計判断の記録は `docs/adr/` に置く。コードから読み取れない「なぜそう決めたか」と
「何を捨てたか」を残すのが目的で、実装手順書ではない。

## 採番

- **既存の最大番号 + 1**（`ls docs/adr/` で確認する）。ファイル名は
  `NNN-kebab-case-slug.md`（3 桁ゼロ埋め）。見出しは `# ADR-NNN: <タイトル>` で、
  ファイル名の番号と一致させる
- **欠番は許容する。** 破棄した ADR の番号は再利用しない（同じ番号が別の判断を
  指すと、過去の PR・コミットからの参照が壊れる）
- **並行ブランチで番号が衝突したら、後発（後からマージする側）がリネームする**。
  ファイル名・見出し・他 ADR からの参照リンクをまとめて直す

### PR 単体では番号重複を検出できない

`claude/new-session-*` が並行する運用では、2 つのセッションがそれぞれ
`007-foo.md` と `007-bar.md` を作ることが起こり得る。**ファイル名が違うので
git は競合を出さず、両方がマージされる**。各ブランチには片方の ADR しか無いため
chaos `x21` も PR 上では緑になり、**main への push で初めて落ちる**
（CI が `push: branches: [main]` を持つのでそこが検出点）。
「なぜ PR で気づけなかったのか」ではなく、これが想定どおりの検出タイミングである。

main が落ちたら、後発の ADR を最大番号 + 1 へリネームして直す。

## テンプレート

```markdown
# ADR-NNN: <決定を一文で>

## ステータス

Accepted（YYYY-MM-DD）

## コンテキスト

何が起きていて、なぜ判断が必要になったか。選択肢が複数あるならここで挙げる。

## 決定

何を決めたか。実装の詳細ではなく、決定そのものを書く。

## 理由

なぜその選択肢を採ったか。捨てた案を捨てた理由も書く（推奨・任意）。

## 影響

この決定によって何が変わるか。制約・残る宿題・後続作業。
```

- **必須は 4 節**（ステータス / コンテキスト / 決定 / 影響）。chaos `x21` が検査する
- **「理由」は 5 節目として推奨**。必須にしない理由は、ADR-005 のように理由が
  「決定」と「検討した代替案」に分散する書き方も成立するため。空に近い「理由」節を
  形式的に置くよりは、書き方の自由を残す
- 上記以外の節（`## 検討した代替案` 等）は自由に足してよい

## ステータス

| 値 | 意味 |
|---|---|
| `Proposed` | 提案中。まだ従わなくてよい |
| `Accepted` | 有効。現行の規約 |
| `Superseded` | 別の ADR に置き換えられた |
| `Deprecated` | 有効でなくなった（置き換え先は無い） |

- 語彙は chaos `x21` の `KNOWN_STATUSES` が単一ソース。`Accepted（2026-07-25）` のように
  日付を付けてよい（先頭語だけを検査する）
- **決定を覆すときは既存 ADR を書き換えず、新しい ADR を立てる。** 旧 ADR は
  `Superseded by [ADR-NNN](NNN-....md)` にステータスだけ更新し、本文は当時のまま残す
  （なぜその判断だったかが失われると、覆した理由も読めなくなる）

## 例外を作る ADR は、被例外側にも追記する

ある ADR が既存 ADR の例外を作るなら、**被例外側の ADR にも「本 ADR には例外がある」
旨を追記する**。片側にしか書かないと、被例外側を単体で読んだ人が原則を無条件だと
誤解する。

追記先は被例外側の「影響」節（または「決定」節）で、例外 ADR へのリンクを張る。
例外が増えたら列挙する。

## 注意

- ADR は**判断の記録**であって仕様書ではない。手順は `.claude/rules/` に、
  実装計画は `docs/dev/` に書く
- **main に既に入った ADR** の内容・番号・ファイル名は変更しない（ステータス更新と
  例外の追記は除く）。採番衝突の解消でリネームしてよいのは、まだマージされていない
  後発ブランチ側の ADR だけ
- ADR を足したら `npx vitest run cli/__tests__/chaos/conventions/x21-adr-consistency.test.ts`
  で採番・構成を確認する
